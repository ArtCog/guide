# START: пайплайн скиллов Мэтта Покока с нуля

Этот файл для ИИ-агента. Человек отдал его тебе, чтобы ты поставил скиллы Мэтта Покока
(github.com/mattpocock/skills, лицензия MIT) и провёл его по первой задаче через весь пайплайн.
Общайся с человеком на его языке. Он может не быть программистом.

## 1. Установка

Определи, в каком агенте ты работаешь, и поставь набор официальной командой из README автора:

**Claude Code**
```
claude plugin install mattpocock-skills@claude-plugins-official
```

**Codex**
```
codex plugin marketplace add mattpocock/skills
codex plugin add mattpocock-skills@mattpocock
```

**GitHub Copilot (CLI)**
```
copilot plugin marketplace add mattpocock/skills
copilot plugin install mattpocock-skills@mattpocock
```

**Gemini CLI**
```
gemini skills install https://github.com/mattpocock/skills.git --path skills/engineering
gemini skills install https://github.com/mattpocock/skills.git --path skills/productivity
```

**Cursor, OpenCode, Windsurf, Amp и другие**
```
npx skills@latest add mattpocock/skills -a <agent>
```

Если команда не сработала, открой README репозитория и возьми актуальную. Не ставь набор двумя
способами сразу: автор предупреждает, что тогда каждый скилл окажется дважды. Если `grill-me` или
`grilling` уже лежат отдельной папкой в `~/.claude/skills/` (например, из архива grill-me), скажи об этом
человеку и предложи убрать эту копию до установки плагина. Сам без его согласия не удаляй.

Проверь, что есть `/retro` и `/implement-spec`. Их нет в старых версиях. Если не видно, обнови
плагин штатным способом своего агента (в Claude Code через `/plugin`).

## 2. Как вызываются команды (объясни человеку)

- Дорогие шаги (`/grill-me`, `/to-spec`, `/to-tickets`, `/implement`, `/retro` и другие) автор нарочно
  сделал такими, что агент сам их не запускает. Их вводит человек. Твоя работа здесь подсказывать,
  какую команду ввести следующей и что подготовить.
- В Claude Code имена идут с приставкой плагина: `/mattpocock-skills:grill-me`. Команда срабатывает,
  только если стоит в самом начале сообщения. Вписанная в середину текста, она приедет обычными словами.

## 3. Подготовка проекта

1. Нужна папка проекта под git. Если её нет, создай папку и выполни `git init`. Без git не будет коммитов
   после `/implement` и диффа для `/code-review`.
2. Попроси человека ввести `/setup-matt-pocock-skills`. Он один раз на проект спрашивает, где хранить
   задачи и куда класть документы. Если GitHub не нужен, советуй хранить задачи локальными файлами.

## 4. Первая задача

1. Спроси одной фразой, что человек хочет сделать. Если он не знает, предложи стартовые фразы из
   `PROMPTS.md`.
2. Оцени размер вместе с ним:
   - **на один вечер** (одна сессия): `/grill-with-docs` → `/implement` прямо в этом же окне;
   - **больше одной сессии**: `/grill-with-docs` → `/to-spec` → `/to-tickets` → `/implement` по одному
     тикету → `/retro`;
   - **огромный и туманный проект** (непонятно даже, какие решения принимать): `/wayfinder`, а когда
     путь прояснится, `/to-spec`.
3. Если вопрос не решить разговором (как должен выглядеть экран, как ведёт себя логика), предложи
   `/prototype`: черновой вариант, на который человек посмотрит и скажет, что не так.
4. Во время допроса решения принимает человек. Факты (что есть в папке, какие версии, что умеет сервис)
   ищи сам и не спрашивай о них.

## 5. Правила контекста

- Допрос, ТЗ и тикеты делаются в одном непрерывном окне, без сжатия до конца `/to-tickets`.
- Перед каждым тикетом `/clear`: тикет самодостаточен, прошлый контекст только мешает.
- Если окно подходит к пределу до `/to-tickets`, сожми контекст на ближайшей границе шагов (`/compact`).
- Хочешь собрать всё ТЗ разом, без ручного прохода по тикетам: `/implement-spec`. Он раздаёт тикеты
  параллельным исполнителям и собирает работу в одну ветку.

## 6. Когда закончили

Попроси человека ввести `/retro` в той же сессии, до `/clear`. Покажи его предложения и внеси только
те, на которые он согласился.

## 7. План на первую неделю (по желанию)

- День 1: установка, `/setup-matt-pocock-skills`, одна задача на вечер через `/grill-with-docs` → `/implement`.
- День 2-3: задача побольше через полный путь с `/to-spec` и `/to-tickets`.
- День 4: `/prototype` для того, что надо увидеть глазами.
- День 5: `/retro` по прошлым сессиям, правки обвязки агента.
- Дальше: `/grill-me` для любых планов без кода (ролик, переезд, покупка).
